# transcription/

## Назначение

Модуль потоковой транскрипции (Speech-to-Text) на базе faster-whisper.
Единственная ответственность: превращать сырой PCM-звук в текст.
Ничего не знает об аудиоустройствах (capture/), UI или LLM —
данные подаёт и забирает Orchestrator.

## Входные данные

- Сырые PCM-чанки: `bytes`, int16, little-endian (как отдаёт capture/).
- Параметры входа: `input_sample_rate` (обычно 48000 Гц) и
  `input_channels` (обычно 1 после mono-микса capture).
  После изменения этих полей нужно вызвать `recompute_window()`.
- Конфигурация — `TranscriptionConfig`:
  - `model_size` — размер модели Whisper (по умолчанию "small");
  - `window_duration_sec` — длина окна накопления в секундах
    (по умолчанию 5.0, меняется без правки кода);
  - `language` — подсказка языка ("ru" и т.п.), None = автоопределение;
  - `silence_rms_threshold` — порог тишины (RMS в шкале int16),
    окна тише пропускаются.

## Выходные данные

- `feed(pcm) -> list[str]` — тексты всех окон, заполнившихся этим чанком
  (обычно пустой список или один-два фрагмента).
- `flush() -> list[str]` — транскрипция незавершённого остатка буфера
  (вызывается при остановке).
- Строки — уже очищенные (`strip()`), пустые сегменты отфильтрованы.

## Ограничения

- Не потоковое декодирование в реальном смысле: текст появляется
  по окончании каждого окна (задержка ≈ window_duration_sec).
- Окна режутся по времени, не по паузам речи — слово на границе окна
  может распознаться неточно или разорваться.
- Ресемплинг — линейная интерполяция (достаточно для речи, не для Hi-Fi).
- Тихие окна отбрасываются целиком (защита от галлюцинаций Whisper);
  очень тихая речь может быть пропущена — порог настраивается.
- Остаток короче 0.5 с при `flush()` игнорируется.
- `load_model()` обязателен до первого `feed()`; первая загрузка модели
  может скачивать её из сети.
- Модель работает на CPU (device="cpu", int8) — скорость зависит от
  размера модели; "small" на слабом CPU может отставать от реального
  времени при коротких окнах.

## Второй input-path: post-stop transcription (file_transcriber)

`transcription/file_transcriber.py::transcribe_file(path)` — НЕ второй
STT-движок, а второй путь к ТОМУ ЖЕ faster-whisper backend. Вместо
живого PCM-потока он читает УЖЕ записанный WAV, ресемплит к 16 кГц mono
float32 и возвращает RAW сегменты `{start, end, text, confidence}` с
таймингами относительно начала файла. Используется Orchestrator-ом в
post-stop транскрипции (Sprint 11): готовые WAV транскрибируются и
RAW TranscriptSegments сохраняются в SQLite на каждый AudioTrack. Это НЕ
online/streaming транскрипция — обработка завершённого файла.
