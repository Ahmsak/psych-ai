## Process Scripts / Session Frames

### Статус
Архитектурная гипотеза. Не предназначена для реализации на текущем этапе MVP.

### Проблема
Психологический помощник работает с потоковой транскрипцией. LLM получает не всю сессию, а небольшие чанки текста, поэтому ей сложно удерживать понимание терапевтического процесса.

### Идея
Помимо памяти, суммаризации и накопленного контекста, исследовать отдельный уровень "Process Scripts" (или "Session Frames"), описывающий текущее состояние терапевтического процесса.

Возможные сценарии:
- знакомство;
- установление контакта;
- диагностика;
- исследование;
- формирование гипотез;
- интервенция;
- работа с сопротивлением;
- кризис;
- нарушение границ;
- эмоциональная поддержка;
- завершение;
- подведение итогов.

Каждый сценарий потенциально может содержать:
- условия входа;
- условия выхода;
- цели;
- допустимые рекомендации;
- ограничения;
- признаки перехода;
- рекомендуемые действия.

Также исследовать отдельные сценарии, работающие по событиям (event-driven):
- нарушение этических границ;
- высокий эмоциональный дистресс;
- суицидальные маркеры;
- длительное молчание;
- уход от темы;
- сопротивление;
- завершение времени сессии.

### Возможные реализации
Пока не выбирать реализацию.

Рассмотреть в будущем:
- SessionState;
- Process Agent;
- конечный автомат (State Machine);
- rule engine;
- специализированные промпты;
- event-driven архитектуру;
- гибрид правил и LLM.

### Примечание
Главная идея — LLM должна понимать не только содержание разговора, но и текущий этап терапевтического процесса. Решение о реализации принимать только после появления рабочего MVP и накопления практического опыта.
