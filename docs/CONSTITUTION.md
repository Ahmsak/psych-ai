# CONSTITUTION — PsychAI

Практически неизменяемый документ. Меняется только при изменении
философии или долгосрочного видения проекта.

## Миссия

Система ассистирует психологу, а НЕ заменяет психолога.
Ответственность и решения всегда остаются за человеком.

## Философия

- Память хранит факты, а не выводы.
- Каждый вывод должен быть прослеживаем до доказательств (evidence).
- Неопределённость должна быть явной.
- Конкурирующие гипотезы допустимы.
- Этика централизована; Constitution независима от LLM.

## Долгосрочное видение

- Мультиагентная система (агенты-аналитики поверх транскрипта сессии).
- Долговременная память, модель эпизодов, нарративный агент.
- Валидатор рекомендаций до показа психологу.

## Архитектурные принципы (обязательны)

1. Orchestrator — единственный координатор. Он создаёт компоненты,
   соединяет их и управляет жизненным циклом (start/stop).
2. Orchestrator НИКОГДА не транспортирует потоковые данные.
   Сырой PCM не проходит через Orchestrator: поток идёт напрямую
   между специализированными компонентами (capture → transcription).
3. Модули не общаются друг с другом напрямую — только через связи,
   явно созданные Orchestrator'ом.
4. Одна ответственность на модуль:
   capture/ — получение аудио; transcription/ — Speech-to-Text;
   llm/ — анализ текста; ui/ — интерфейс; session/ — сессия;
   orchestrator/ — координация.
5. Markdown — единственный источник истины знаний проекта.
   Любые индексы (SQLite/FTS/векторные) — производные и полностью
   восстанавливаются из Markdown.
6. Система знаний проекта остаётся простой, понятной, независимой от
   конкретного человека или конкретной LLM и обеспечивает возможность
   многолетней разработки проекта.

## Ограничения

- Не переписывать рабочий код без объективной причины.
- Минимальные изменения предпочтительнее «красивых» переписываний.
- Архитектурные решения не принимаются агентом самостоятельно:
  сначала предложение (зачем / альтернативы / плюсы / минусы),
  затем подтверждение владельца проекта.
- Среда не переустанавливается и версии библиотек не меняются
  без необходимости; проблемы среды сначала сообщаются.

## Критерии качества

- Рабочий MVP важнее идеальной незавершённой архитектуры.
- Каждое изменение проверяется реальным запуском (e2e где возможно).
- Корректное завершение: никаких зависших потоков и утёкших ресурсов.
- Документация обновляется по правилам жизненного цикла
  (см. docs/DOCUMENTATION_LIFECYCLE.md).
