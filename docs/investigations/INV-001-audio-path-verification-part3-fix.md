## Проблема №1 — причина и что исправлено

### Установленная причина
Реплики психолога отсутствуют, потому что микрофон записал почти пустой
сигнал (peak 3.6% шкалы) → Whisper вернул 0 сегментов → mic_segments.json
пуст → Conversation psy=0. Это НЕ баг конвейера: та же функция
`_transcribe_segments` на loopback дала 19 сегментов; путь захвата mic
(`stream.read`→`to_unified`→запись) уровень не занижает.

### Что реально было кодовым дефектом (и исправлено)
Проблему МАСКИРОВАЛО расхождение двух путей транскрипции:
- `mic_transcription.txt` писался через StreamingTranscriber (окна) →
  на почти-тишине Whisper ГАЛЛЮЦИНИРОВАЛ текст → файл выглядел рабочим;
- `mic_segments.json` писался через `m.transcribe()` целиком → 0.
Из-за этого sensor-проверка «есть текст → есть транскрипция» проходила,
а Conversation (по сегментам) молча терял психолога.

### Исправление (минимальное, без рефакторинга/смены архитектуры)
1. `tools/run_timeline_experiment.py`: текст транскрипции теперь берётся
   из ТОГО ЖЕ сегментного пути (`mic_text = "\n".join(seg.text ...)`),
   что и `*_segments.json`. Два артефакта больше не могут расходиться;
   галлюцинаций-фантомов на тишине нет.
2. `tools/check_experiment.py` + `tools/run_integration_validation.py`:
   добавлена sensor-проверка «transcription/segments consistency» —
   непустой .txt при 0 сегментов → FAIL (ловит именно этот класс ошибки).
3. Тест `tests/test_integration_harness.py::
   test_conversation_stage_flags_txt_segments_mismatch` фиксирует, что
   рассинхрон впредь падает.

### Пересборка артефактов этого эксперимента (без повторного Whisper,
### без фабрикации)
- `mic_transcription.txt`/`loopback_transcription.txt` перегенерированы из
  уже имеющихся сегментов: mic → 0 симв. (честно пусто), loopback → 740.
- `conversation.json` перестроен: 19 реплик (client), psychologist=0.
- Session/Statistics: utt=19, psy=0, cli=19, words=135; validate=WARNING
  `no psychologist utterances` — теперь это ПРАВДИВЫЙ сигнал, а не
  замаскированный.
- `check_experiment` теперь честно FAIL: «microphone: no transcription
  despite audio (rms_max=386.9)» — раньше это скрывалось галлюцинацией.
- `run_integration_validation`: Overall WARNING (0 FAIL) — корректно
  отражает отсутствие голоса психолога в АУДИО.
- pytest: 70 passed.

### Важно
Число реплик психолога НЕ «починено» в 19 — их в аудио нет, создавать их
было бы фабрикацией. Исправлен код-дефект маскировки; фактическая причина
(тихий микрофон) устраняется на записи (см. №2 и рекомендации).

## Ответы на инженерные вопросы

**Почему тесты не поймали №1?** Существующие тесты работали на
синтетических сегментах (проверяли логику сборки), а sensor смотрел на
`*_transcription.txt`, который был непуст из-за галлюцинаций. Пустой
`mic_segments.json` (реальный вход Conversation) не проверялся.

**Какой тест добавлен?** Sensor «transcription/segments mismatch»
(в check_experiment и harness) + unit-тест на FAIL при рассинхроне.

**Другие места незаметной потери данных?** Везде, где одни данные имеют
два представления: (a) `*_transcription.txt` vs `*_segments.json` —
устранено; (b) Conversation берёт реплики только из segments — если
segments пусты по любой причине, сторона исчезает (теперь ловится новым
sensor); (c) большой timeline-offset (13 с) не теряет данные, но сдвигает
— стоит логировать порог (рекомендация, не исправление).

## Проблема №2 — вывод (НЕ исправляется)
Смешивание происходит ДО попадания данных в PsychAI: голос клиента
физически присутствует в сыром mic.wav (corr огибающих 0.952 при сдвиге,
равном offset loopback; уровень mic растёт вместе с громкостью клиента).
В коде PsychAI микширования нет. Причина — аудио-тракт Windows:
акустическая утечка (динамики/открытая гарнитура → микрофон) и/или
Realtek Stereo Mix / «Прослушивать это устройство» / boost.

Согласно правилу: код не меняется. Рекомендации (диагностика):
- mmsys.cpl → Запись → Микрофон → «Прослушивать это устройство» ВЫКЛ;
  «Уровни» boost 0 dB; отключить Stereo Mix.
- Тест с закрытыми наушниками (пропадает ли клиент из mic).
- Тест «психолог говорит, в звонке тишина» — проверить чистоту голоса
  психолога и поднять уровень микрофона.

## Архитектуру Audio Capture менять НЕ нужно
Оба дефекта — во входном аудио (до PsychAI). Захват (ADR-006) записал
ровно то, что отдали устройства, потоки не смешивал, тайминги/метаданные
зафиксировал верно. Смена архитектуры не вернёт незаписанный голос и не
устранит акустическую/драйверную утечку — это лечится на уровне
Windows/железа. Менять работающую архитектуру ради внешней причины
противоречит принципам проекта.
