# VERSIONING — версионирование PsychAI

Предложение (Sprint 3.6, п.8). Реализация (теги, файл версии) — по
решению владельца, отдельным шагом.

## Схема: упрощённый SemVer — MAJOR.MINOR.PATCH

- MAJOR (0 → 1): первый выпуск, пригодный для реального использования
  психологом. Пока продукт в MVP-стадии — MAJOR = 0.
- MINOR (+1): завершение Sprint, добавляющего функциональность
  (новый модуль, новая возможность конвейера).
- PATCH (+1): исправления и мелкие правки без новой функциональности.

Инфраструктурные спринты (знания/документация, как 3.5/3.6) версию
ПРОДУКТА не меняют.

## Ретроспективное соответствие

| Версия | Состояние |
|---|---|
| 0.1.0 | Скелет: GUI + Session + Orchestrator (Sprint 0) |
| 0.2.0 | capture/ — WASAPI loopback захват (Sprint 1–2) |
| 0.3.0 | MVP потоковой транскрипции (Sprint 3) — ТЕКУЩАЯ |

Будущие: 0.4.0 — следующий функциональный Sprint (например LLM);
1.0.0 — первый пригодный для практики выпуск.

## Правила (когда версионирование будет внедрено)

1. Версия фиксируется git-тегом: `git tag v0.3.0 && git push --tags`.
2. Тег ставится только на коммит, прошедший DEFINITION_OF_DONE.
3. Версия упоминается в PROJECT_STATE.md (Last Update).
4. Отдельный VERSION-файл/`__version__` в коде — не требуется до 1.0.0
   (лишняя синхронизация); источник истины — git-теги.
