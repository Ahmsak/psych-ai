# DEVELOPMENT_WORKFLOW — цикл разработки PsychAI

Понятен новому разработчику/агенту без дополнительных объяснений.
Обновляется при изменении процесса разработки.

## Полный цикл рабочей сессии

1. Получить последние изменения
       git pull --ff-only
2. Проверить окружение
       python tools/verify_environment.py
   Если RESULT: FAIL — НЕ чинить среду молча; сообщить владельцу
   (правило из docs/ENVIRONMENT.md).
3. Восстановить контекст
   Прочитать START_HERE.md и документы по указанному там порядку
   (минимум: PROJECT_STATE.md и SESSION.md — текущая цель и последний шаг).
4. Выполнить задачу спринта
   - Правила: docs/CONSTITUTION.md (архитектура), минимальные изменения,
     не переписывать рабочий код без причины.
   - Архитектурные изменения — только после предложения
     (зачем/альтернативы/плюсы/минусы) и подтверждения владельца.
5. Протестировать
   - Реальный запуск затронутого пути (например run_stream.py для STT).
   - Ручные проверки: tests/ (например tests/capture_live_check.py).
6. Обновить документацию
   По таблице docs/DOCUMENTATION_LIFECYCLE.md. Как минимум SESSION.md
   после каждой сессии; PROJECT_STATE.md после каждого Sprint;
   ADR при новом архитектурном решении.
7. Зафиксировать в Git
       git status          # убедиться, что в коммит идёт только нужное
       git add <files>
       git commit -m "тип: краткое описание"
       git push
8. Завершение Sprint
   Пройти чек-лист docs/DEFINITION_OF_DONE.md. Sprint завершён только
   когда выполнены ВСЕ пункты.

## Git Workflow

### Когда делать commit
- Логически завершённый шаг (модуль, документ, исправление) — один
  осмысленный коммит. Не копить работу нескольких дней.
- Рабочее состояние: код после коммита запускается (verify + smoke-тест).
- Документация коммитится вместе с кодом, который она описывает.

### Когда делать push
- После каждого коммита или, минимум, в конце каждой рабочей сессии.
- Обязательно в конце Sprint (пункт Definition of Done).
- Незапушенная работа существует только на одной машине и может быть
  потеряна — см. «Роль GitHub» ниже.

### Ветки
- main — основная ветка; MVP-стадия, один разработчик: работаем в main.
- Отдельная ветка (sprint-N-название / feat-название) — когда:
  - экспериментальное/рискованное изменение, которое может не войти;
  - параллельно работают несколько разработчиков или агентов;
  - изменение растянется на несколько сессий и сломает main в процессе.
- Ветка вливается в main после прохождения Definition of Done.

### Стиль сообщений коммитов
Формат: `тип: краткое описание в повелительном наклонении`
- feat:     новая функциональность (feat: add streaming transcriber)
- fix:      исправление ошибки
- docs:     только документация
- refactor: изменение кода без изменения поведения
- test:     тесты и проверки
- infra:    инфраструктура (tools/, CI, конфигурация)
Язык сообщений: английский (как в существующей истории репозитория).

## Роль GitHub

Репозиторий: https://github.com/Ahmsak/psych-ai

GitHub — это:
1. Резервная копия проекта. Локальная машина может умереть в любой
   момент; всё, что запушено, — переживёт.
2. Долговременная история разработки: каждое решение можно проследить
   по коммитам, diff'ам и датам через годы.
3. Средство восстановления: новая машина поднимается за минуты:
       git clone https://github.com/Ahmsak/psych-ai.git
       cd psych-ai
       pip install -r requirements.txt
       python tools/verify_environment.py
       # дальше — START_HERE.md
4. Точка входа для новых разработчиков и ИИ-агентов (вся система
   знаний — Markdown в репозитории, ADR-006).

Следствие: работа, не отправленная в GitHub, считается НЕ сохранённой.
