# ARCHITECTURAL_DECISIONS — PsychAI (ADR log)

Журнал архитектурных решений. Только добавление записей; существующие
записи не редактируются (кроме статуса). Обновляется при принятии
нового архитектурного решения.

Формат: номер, дата, контекст, решение, мотивация, последствия.

---

## ADR-001 — Orchestrator как единственный координатор

- Дата: 2026-06 (начало проекта)
- Контекст: нужен способ связать модули (UI, Session, Capture,
  Transcription, будущие Memory/Agents/Validator) без спагетти-связей.
- Решение: все связи между модулями создаёт только Orchestrator;
  модули никогда не обращаются друг к другу напрямую.
- Мотивация: единая точка координации, простая замена модулей,
  тестируемость каждого модуля в изоляции.
- Последствия: у каждого модуля узкий публичный интерфейс; добавление
  связи = изменение только Orchestrator.

## ADR-002 — PyAudioWPatch для захвата системного звука

- Дата: 2026-07 (Sprint 1)
- Контекст: нужен захват «что слышно» (Zoom/Meet/браузер) на Windows.
  Рассмотрены sounddevice (нет loopback без пересборки PortAudio),
  soundcard (хобби-проект, баги), pycaw (только громкость, не захват),
  нативный WASAPI через ctypes (максимум работы).
- Решение: PyAudioWPatch (форк PortAudio с WASAPI loopback, готовое wheel).
- Мотивация: работает из коробки, стабильный, покрывает сценарий
  «звук сессии идёт через устройство вывода».
- Последствия: захватывается ВЕСЬ системный микс; per-application
  захват потребует нативного WASAPI process-loopback (отдельный спринт);
  в API поле process_id зарезервировано и бросает NotImplementedError.

## ADR-003 — faster-whisper (ctranslate2, CPU int8) для STT

- Дата: 2026-07 (Sprint 2/3)
- Контекст: нужна локальная транскрипция русской/английской речи без
  облака (конфиденциальность сессий психолога).
- Решение: faster-whisper, модель small, device=cpu, compute_type=int8.
- Мотивация: локально, приватно, приемлемая скорость на CPU, простое API.
- Последствия: скорость зависит от CPU; large-модели потребуют GPU;
  зависимость от ctranslate2/onnxruntime.

## ADR-004 — Окна фиксированной длительности вместо потокового декодера

- Дата: 2026-07 (Sprint 3)
- Контекст: MVP потоковой транскрипции; настоящий streaming decoder,
  partial results, overlap — сложны и отложены.
- Решение: накапливать PCM в окна window_duration_sec (конфиг,
  по умолчанию 5.0 с) и транскрибировать окно целиком.
- Мотивация: минимальный работающий конвейер; параметр меняется без кода.
- Последствия: задержка ≈ размеру окна; слова на границе окна могут
  рваться. Overlap/endpoint detection — кандидаты будущих спринтов.

## ADR-005 — Данные текут напрямую между компонентами, минуя Orchestrator

- Дата: 2026-07 (Sprint 3)
- Контекст: первая реализация гоняла PCM через цикл в Orchestrator,
  что смешивало координацию с транспортом данных.
- Решение: Orchestrator только создаёт/соединяет/останавливает.
  Сырой PCM идёт напрямую: transcriber.run() потребляет
  capture.iter_chunks(); текст уходит в переданный sink (консоль).
- Мотивация: разделение ответственности: «Оркестратор управляет
  системой, а не переносит данные» (принципиальное требование проекта).
- Последствия: у транскрайбера есть метод run(chunks, on_text);
  будущая pub/sub-модель (capture.register_callback уже существует)
  станет естественным расширением, когда появится второй подписчик.

## ADR-006 — Markdown как единственный источник истины знаний проекта

- Дата: 2026-07 (Sprint 3.5)
- Контекст: проект должен быть независим от памяти конкретного
  разработчика или конкретной LLM; новый агент должен стартовать < 2 мин.
- Решение: все знания проекта — в Markdown (корень: START_HERE.md;
  остальное в docs/). Любые индексы (SQLite FTS5, векторные БД) — только
  производные представления, полностью восстановимые из Markdown.
  Индекс на данном этапе НЕ реализуется (см. docs/MEMORY_ARCHITECTURE.md).
- Мотивация: git-версионируемость, читаемость человеком и любым агентом,
  нулевая стоимость сопровождения, отсутствие рассинхронизации.
- Последствия: документы обновляются по правилам
  docs/DOCUMENTATION_LIFECYCLE.md; при росте объёма знаний возможен
  переход к варианту Б (Markdown + индекс) по критериям из
  MEMORY_ARCHITECTURE.md.
