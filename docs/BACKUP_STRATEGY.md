# BACKUP_STRATEGY — стратегия резервного копирования PsychAI

Обновляется при изменении состава артефактов или процедур бэкапа.

## Источник истины

1. Знания проекта — Markdown в репозитории (ADR-006):
   START_HERE.md + docs/* + README модулей. Никакие знания не живут
   только в индексах или чьей-то памяти.
2. Код — исходники в репозитории.
3. Версии зависимостей — requirements.txt.

Источник истины ВСЕГДА в Git; всё остальное — производное.

## Что хранится в Git (локальный репозиторий)

- Весь исходный код (capture/, transcription/, orchestrator/, ui/,
  session/, llm/, utils/, tests/, tools/, sandbox/).
- Вся система знаний (START_HERE.md, docs/, README, ROADMAP).
- Конфигурация проекта (.gitignore, requirements.txt).
- Точки входа (main.py, app.py, run_stream.py).

## Что хранится в GitHub (origin)

То же самое, что в Git: GitHub — удалённая копия репозитория
(https://github.com/Ahmsak/psych-ai) и выполняет роли:
- резервная копия (переживает потерю машины);
- долговременная история разработки;
- средство восстановления (см. docs/DISASTER_RECOVERY.md).

Правило: каждый завершённый Sprint запушен (DEFINITION_OF_DONE п.8).
Работа, не отправленная в GitHub, считается НЕ сохранённой.

## Что НЕ должно храниться в репозитории

- Секреты: API-ключи, токены, пароли (.env — в .gitignore; при
  появлении LLM-ключей описать восстановление в DISASTER_RECOVERY.md).
- Персональные данные и записи сессий психолога (конфиденциальность;
  при появлении Storage — отдельная стратегия и ADR).
- Большие бинарные артефакты: аудиофайлы (*.wav в .gitignore),
  веса моделей.
- Производные артефакты (ниже) — всё, что восстанавливается
  автоматически.

## Производные артефакты (НЕ бэкапить, восстанавливаются сами)

| Артефакт | Как восстанавливается |
|---|---|
| __pycache__/, *.pyc | пересоздаёт Python при запуске |
| .pytest_cache/ | пересоздаёт pytest |
| venv / .venv | pip install -r requirements.txt |
| SQLite-индексы (будущие) | tools/reindex.py из Markdown (MEMORY_ARCHITECTURE) |
| FTS-индексы (будущие) | то же — полная пересборка из Markdown |
| Векторные базы (будущие) | то же — пересчёт эмбеддингов из Markdown |
| Кэш HuggingFace (~/.cache/huggingface) | автоскачивание модели при первом запуске |
| Временные файлы (tmp/, *.tmp, ad-hoc скрипты проверок) | не нужны — пересоздаются по мере работы |
| .vscode/ и настройки IDE | локальные предпочтения, не знания проекта |

Принцип: если артефакт можно детерминированно восстановить из
источника истины — он производный и в бэкап не входит.

## Текущее покрытие .gitignore

    .venv/  __pycache__/  *.pyc  .vscode/  *.wav

При появлении новых производных артефактов (.pytest_cache, *.db,
.env) — добавлять их в .gitignore СРАЗУ, до первого появления в
git status.

## Процедуры

- Ежесессионно: git push в конце сессии (DEVELOPMENT_WORKFLOW).
- По завершении Sprint: push обязателен (DEFINITION_OF_DONE п.8).
- Проверка: git status чистый, origin/main не отстаёт от main.
- Восстановление: docs/DISASTER_RECOVERY.md.
