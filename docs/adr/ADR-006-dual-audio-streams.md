# ADR-006: Два независимых аудиопотока (Microphone + WASAPI Loopback)

## Status
Accepted

## Context
Для захвата разговора (напр. звонок в мессенджере) нужны оба голоса:
локальный пользователь и удалённый собеседник. Эксперименты Sprint 4.0
показали: WASAPI Loopback записывает только собеседника (то, что
рендерится в устройство вывода), голос пользователя в нём отсутствует.
Ни один одиночный штатный механизм Windows не отдаёт оба голоса одним
потоком. Рассмотренные альтернативы: Virtual Audio Cable (сторонний
драйвер, сложная установка для психолога), перехват процесса
(process-loopback — нативный ctypes/comtypes, дорого, всё равно без
голоса пользователя), интеграция с API мессенджеров (закрытые/
отсутствуют, привязка к конкретному приложению).

## Decision
Использовать два независимых потока захвата: default Microphone (голос
пользователя) и WASAPI Loopback (голос собеседника). Потоки
записываются и транскрибируются раздельно, без объединения и
синхронизации на этом этапе.

## Consequences
- (+) Оба голоса доступны штатными средствами Windows, без сторонних
  драйверов и без привязки к конкретному мессенджеру.
- (+) Естественное разделение источников (кто говорит) без diarization.
- (+) Переиспользует уже существующие модули capture/ и transcription/.
- (−) Два потока с разными частотами дискретизации (напр. 44100 и
  48000 Гц) — обрабатываются раздельно.
- (−) Без наушников возможно эхо собеседника в микрофонном потоке.
- Отложено (не входит в решение): объединение потоков, синхронизация,
  diarization, VAD, LLM-анализ.
