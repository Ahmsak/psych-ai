# ADR-008: Conversation Builder — source-based speaker + сегментные тайминги

## Status
Accepted

## Context
Sprint 7 строит единый упорядоченный по времени диалог (Conversation)
из двух независимых транскрипций. Нужны два решения:
1. Как назначать говорящего (speaker) без диаризации и LLM.
2. Откуда брать время каждой реплики, если транскрипт Sprint 5 хранил
   только текст, без таймингов сегментов.

Ограничения спринта: НЕ диаризация, НЕ LLM, НЕ анализ, текст Whisper
не менять.

## Decision
1. Speaker назначается по ИСТОЧНИКУ дорожки (source-based, не
   диаризация): microphone → psychologist, loopback → client. Это
   объективное соответствие (кто в какой поток говорит), а не анализ
   голоса.
2. Данные о таймингах реплик берутся из НАТИВНЫХ сегментов faster-whisper
   (seg.start/end/avg_logprob). Экспериментальный слой
   (tools/run_timeline_experiment.py) дополнительно сохраняет
   <track>_segments.json; текст сегмента не изменяется. Абсолютное время
   реплики = offset дорожки (из timeline, ADR-007) + seg.start.
3. Conversation Builder — первый ПРОДУКТОВЫЙ модуль: пакет
   conversation/ (model + builder + API), часть Session-слоя данных,
   не экспериментальная утилита в tools/.

## Consequences
- (+) «Бесплатное» разделение говорящих без диаризации: источник дорожки
  однозначно определяет роль.
- (+) Тайминги реплик берутся из уже существующих данных Whisper; текст
  не трогаем; conversation.json — источник истины для будущего анализа.
- (+) Продуктовый код отделён от исследовательского (conversation/ vs
  tools/); архитектура (ось Session) не нарушена.
- (−) Роль привязана к дорожке жёстко (psychologist/client); при иной
  раскладке источников потребуется конфиг сопоставления.
- (−) Тайминги реплик наследуют точность offset (~десятки мс, ADR-007) и
  сегментации Whisper.
- Аудио НЕ объединяется/не диаризуется; выполняется только сборка
  структуры диалога.
