# DOCUMENTATION_LIFECYCLE — правила обновления документации

Кто бы ни завершал работу (человек или агент) — он обновляет документы
по этим правилам. Документация, не обновлённая по правилам, считается
незавершённой работой.

## Когда что обновлять

| Документ | Когда обновляется |
|---|---|
| START_HERE.md | при смене текущего Sprint или способа запуска проекта |
| docs/CONSTITUTION.md | только при изменении философии или долгосрочного видения (редко; фиксируется отдельным решением владельца) |
| docs/ARCHITECTURAL_DECISIONS.md | только при принятии нового архитектурного решения (записи добавляются, не редактируются) |
| docs/PROJECT_STATE.md | после завершения каждого Sprint |
| docs/SESSION.md | после каждой рабочей сессии (новая запись сверху) |
| docs/ENVIRONMENT.md | после изменения окружения или зависимостей |
| docs/DEPENDENCIES.md | при добавлении, удалении или замене библиотек |
| docs/MEMORY_ARCHITECTURE.md | при изменении подхода к памяти проекта (через ADR) |
| docs/DEVELOPMENT_WORKFLOW.md | при изменении процесса разработки или git-правил |
| docs/DEFINITION_OF_DONE.md | при изменении критериев завершения Sprint (через владельца) |
| docs/DISASTER_RECOVERY.md | при изменении процедуры восстановления или состава среды |
| docs/BACKUP_STRATEGY.md | при изменении состава артефактов или процедур бэкапа |
| docs/VERSIONING.md | при изменении схемы версионирования (через владельца) |
| docs/GLOSSARY.md | при появлении новых терминов в архитектуре или предметной области |
| docs/OWNER_DECISIONS.md | при принятии/отмене решения владельцем проекта (только добавление записей) |
| README.md (корень) | при изменении назначения/структуры проекта |
| ROADMAP.md | при завершении Sprint или изменении плана |
| README модулей (capture/, transcription/, ...) | при изменении интерфейса или ограничений модуля |

## Правила

1. Обновление документации — часть Definition of Done спринта/сессии.
2. Markdown — единственный источник истины (ADR-006); сначала документ,
   потом любые производные (индексы, если появятся).
3. Один документ — одна область знаний; не превращать документы в свалку.
4. Новые документы НЕ создаются без необходимости — только при первом
   реальном триггере (новая область знаний, которую существующие
   документы не покрывают).
5. SESSION.md — оперативная память (append-only журнал);
   PROJECT_STATE.md — сводное состояние (перезаписывается).
6. В ADR-журнале прошлые записи не переписываются; изменение решения =
   новая запись со ссылкой на отменяемую.
7. Дата в формате YYYY-MM-DD в каждой записи SESSION.md и в
   Last Update PROJECT_STATE.md.
