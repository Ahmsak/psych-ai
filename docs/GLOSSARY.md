# GLOSSARY — словарь терминов PsychAI

Краткие определения основных терминов. Обновляется при появлении
новых понятий в архитектуре или предметной области.

## Предметная область

- **Session (Сессия)** — одна встреча психолога с клиентом,
  сопровождаемая системой; единица работы приложения (модуль session/).
- **Episode (Эпизод)** — значимый смысловой фрагмент внутри сессии или
  между сессиями (будущая модель эпизодов, см. CONSTITUTION → видение).
- **Fact (Факт)** — атомарное проверяемое утверждение, извлечённое из
  сессии («клиент сказал X»). Память хранит ТОЛЬКО факты, не выводы.
- **Evidence (Доказательство)** — конкретные данные (фрагмент
  транскрипта, наблюдение), на которые опирается вывод. Каждый вывод
  должен быть прослеживаем до evidence.
- **Observation (Наблюдение)** — зафиксированное событие/поведение без
  интерпретации (сырьё для фактов).
- **Hypothesis (Гипотеза)** — предположительная интерпретация фактов;
  всегда с явной неопределённостью; конкурирующие гипотезы допустимы.
- **Narrative (Нарратив)** — связное изложение истории клиента,
  собираемое из эпизодов (будущий нарративный агент).
- **Context (Контекст)** — совокупность информации, доступная
  компоненту при принятии решения (факты, история, текущая сессия).

## Архитектура

- **Orchestrator (Оркестратор)** — единственный координатор системы:
  создаёт компоненты, соединяет их, управляет жизненным циклом.
  НИКОГДА не транспортирует потоковые данные (ADR-005).
- **Agent (Агент)** — специализированный ИИ-компонент, анализирующий
  данные сессии (будущая мультиагентная система). Агенты не общаются
  напрямую — только через Оркестратор.
- **Validator (Валидатор)** — компонент, проверяющий рекомендации на
  соответствие этике/Constitution ДО показа психологу (будущий).
- **Memory (Память)** — хранилище фактов проекта-продукта
  (не выводов); будущий модуль. Не путать с памятью ПРОЕКТА
  (docs/ — знания для разработчиков, см. MEMORY_ARCHITECTURE.md).
- **Constitution (Конституция)** — централизованный, независимый от
  LLM свод этических правил продукта (для разработки — docs/CONSTITUTION.md).

## Аудио/STT-конвейер

- **Capture (Захват)** — получение сырого системного звука Windows
  через WASAPI loopback (модуль capture/, PyAudioWPatch).
- **Loopback** — механизм WASAPI, отдающий копию звука, который
  воспроизводится на устройстве вывода («что слышно»).
- **PCM** — сырые несжатые аудиосэмплы (у нас int16, 48 кГц с устройства).
- **Chunk (Чанк)** — порция PCM фиксированного размера, передаваемая
  из capture в transcription.
- **Streaming (Потоковая обработка)** — обработка звука по мере
  поступления, а не после записи целиком.
- **Transcription (Транскрипция)** — преобразование речи в текст
  (модуль transcription/, faster-whisper).
- **Window (Окно)** — отрезок аудио длиной window_duration_sec,
  транскрибируемый за один вызов модели (ADR-004).
- **RMS-гейт** — отбрасывание почти беззвучных окон по среднеквадратичной
  громкости (защита от галлюцинаций Whisper на тишине).

## Процесс

- **Sprint** — ограниченный этап работы с явными целями и правилами;
  завершается по чек-листу docs/DEFINITION_OF_DONE.md.
- **ADR** — Architectural Decision Record, запись архитектурного
  решения в docs/ARCHITECTURAL_DECISIONS.md.
- **MVP** — минимальный работающий продукт; рабочий MVP важнее
  идеальной незавершённой архитектуры.
